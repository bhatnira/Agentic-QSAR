--------------------------------------------------------------------------------
ABSTRACT
--------------------------------------------------------------------------------

We present Agentic QSAR, a fully autonomous agentic system for developing
quantitative structure-activity relationship (QSAR) models. Given a dataset,
molecular representation and a compute budget, the agent plans experiments,
executes model training with hyperparameter search, evaluates performance under
multiple cross-validation splits, and reflects on failures and trustworthiness
of the current best strategy. Three novel components distinguish the system:
(i) a trust gate that postpones termination until the leading strategy is
validated as predictive, generalizing, robust and covering the applicability
domain, instead of stopping at an arbitrary improvement threshold; (ii) a
read-only knowledge-graph evidence layer that accumulates (fact, subject,
predicate, object) triples across datasets and reallocates computational effort
toward strategies with class-level evidence, while never triggering new
experiments; and (iii) full explainability: every planning decision is
recorded in a machine-readable trace, and evidence for and against any strategy
can be rendered as a human-readable decision board.

We benchmark the agent on six standard ADMET/physicochemical datasets (ESOL,
FreeSolv, Lipophilicity, BACE, BBBP, ClinTox) across five independent seeds
against a static hyperparameter grid baseline, and through three controlled
ablations: (a) hyperparameter search on vs off, (b) trust gate on vs off, and
(c) heuristic vs real-LLM (NVIDIA gpt-oss-20b) strategy selection. (FILL:
overall improvement summary, e.g., "the agent matched or beat the grid baseline
on X of 6 datasets...").

Our objective is not to report state-of-the-art predictive accuracy -- the
benchmark-conditioned comparison is against the identical model library run
under identical folds -- but to demonstrate that an agentic controller can
match or exceed a deterministic automated baseline while spending compute
deliberately, and to provide a reproducible framework for studying agentic
cheminformatics.

Keywords: QSAR; agentic systems; model development; trust; explainability;
hyperparameter search.

--------------------------------------------------------------------------------
1  INTRODUCTION
--------------------------------------------------------------------------------

QSAR modelling is one of the oldest and most widely applied computational
techniques in drug discovery. The classical workflow -- descriptor generation,
model selection, cross-validation, reporting -- is now routinely automated by
benchmarks such as TDC, MoleculeNet-based pipelines, and AutoML frameworks.
What is missing is not accuracy but judgement: decisions about what to try
next, when to stop, whether a model is trustworthy for the intended use, and
-- critically -- a machine-readable account of why the final model was chosen.

Recent "agentic AI" systems couple large language models (LLMs) with tools and
execution loops, and several have been proposed for cheminformatics (research
agents, synthesis planning agents, generalist molecule agents). With a few
exceptions, these demonstrations emphasize LLM ideation rather than rigorous
model development, and they rarely confront the discipline of experimental
budgets, validation protocols, and trust assessment that QSAR practitioners
need.

We design Agentic QSAR to answer one question: can an autonomous agent build a
QSAR model as well as, and more transparently than, a deterministic automated
pipeline, using the same computation budget?

The system is organized as a closed loop (Section 2.1):

  1. PROFILING -- the dataset is characterized (quality, size, task type,
     chemical space) and validated splits are established.
  2. PLANNING -- a candidate generator scores every feasible (representation,
     model, split) strategy under a utility model that blends expected
     improvement, computational cost, evidence from the knowledge layer, and
     with-in-run escalation policy. An LLM may re-rank the candidate list.
  3. EXECUTION -- the chosen strategy is trained under k-fold CV with
     hyperparameter search, producing a full performance record.
  4. EVALUATION -- metrics are computed, including generalization and
     robustness axes beyond the primary score.
  5. TRUST & DIAGNOSIS -- the strategy is scored on predictive quality,
     generalization, robustness, and applicability-domain coverage. Failures
     are diagnosed and fed back to planning (experiments are never re-run).
  6. TERMINATION -- the trust gate decides whether stopping is acceptable.
     Stopping is postponed while the leading strategy is untrustworthy on
     configured axes, up to budget exhaustion.

Contributions. (1) A trust gate that formalizes "when to stop": termination is
advisory-forced -- it can never veto an experiment, it only postpones
stopping -- and yields to budget or candidate exhaustion, so no run can loop
forever. (2) A knowledge-graph evidence layer that accumulates cross-dataset
facts (e.g., "svr with MACCS keys achieves RMSE 0.68 on regression/small
datasets") and reallocates planner effort deterministically, with an empty
store leaving the planner's behaviour unchanged (read-only side car). (3) A
complete, JSONL-format planning trace per run, enabling exact audit of every
decision. (4) A public benchmark protocol with fixed seeds, identical folds
across scenarios, and paired statistical analysis (Wilcoxon signed-rank).

--------------------------------------------------------------------------------
2  METHODS
--------------------------------------------------------------------------------

2.1  Agent architecture

The agent is implemented as a state graph over phases (profiling, planning,
execution, evaluation, trust, diagnosis, termination). Stylized pseudocode:

    loop:
      profile(dataset)                         # quality, size, task, splits
      candidates = plan(case, history, budget, kg_evidence)
      strategy   = top_usable(candidates)      # skips done/failed strategies
      if strategy is None: stop(reasons)  | plan/feasibility/cost budget
      record = execute(strategy)               # CV + hyperparameter search
      verdicts = evaluate_trust(record, case)  # predictive/generalization/
                                                # robustness/application domain
      diagnose(record) if record failed
      decision = decide(candidates_left, no_improvement_rounds, budget, ...)
      decision = trust_gate(decision, verdicts)
      if decision == finalize: break

State is staged between nodes; every node commits only its owned channels, and
the routing bookkeeping is declarative, which is a prerequisite for exact trace
reproduction.

2.2  Planner and candidate utility

The candidate space is the Cartesian product of enabled molecular
representations (MACCS keys, Morgan/ECFP fingerprints, RDKit fingerprints, and
graph encodings where applicable), model families (ridge regression, SVR,
k-nearest neighbours, random forest, extra trees, gradient-boosted trees
(lightgbm when available), MLP, and graph neural networks GCN/GAT/MPNN for the
graph representation), and validated splits (random / stratified / scaffold or
a subset thereof).

Each (representation, model, split) strategy is scored as

  utility = expected_benefit - cost_penalty + evidence_bonus + escalation_boost

  * expected_benefit: an estimate of the attainable gain on the primary metric
    relative to the current best completed experiment, informed by the dataset
    class (task type and size bucket) and validated split history.
  * cost_penalty: a normalized penalty derived from estimated wall-clock cost
    (scaling with dataset size, feature dimensionality, and model family).
  * evidence_bonus: a bounded additive boost (cap 0.25) for strategies with
    class-level evidence in the knowledge layer: 0.05 per supporting fact plus
    0.05 per unit of margin above the class aggregate score, capped.
  * escalation_boost: +0.15 for the best strategy of a representation/model
    family in which the latest completed experiment already outperformed the
    incumbent (winner boost) -- an explicit, non-evolutionary strategy
    escalation policy.

Candidates are ranked by utility; the LLM (when enabled) sees the top 8 ranked
candidates plus the last 5 experiments and may reorder them before the planner
executes the top usable one. "Usable" excludes strategies already completed or
failed with the same settings (signature match), guaranteeing every executed
experiment is novel.

2.3  Trust gate (when to stop)

Without a trust gate, the loop settles as soon as (a) no candidate exceeds a
marginal-improvement threshold or (b) unexplored strategies are exhausted under
the round cap. This is cheap but can terminate with a brittle model, e.g. one
that performs well on random splits but fails on scaffold splits.

The trust gate formalizes stopping. A strategy is trustworthy if configured
trust axes are satisfied. Four axes are assessed per completed experiment:

  * predictive   -- good if the primary metric beats a dataset-class threshold
                    (e.g. RMSE < 1.0 for regression/small, R2 >= 0.5), else
                    moderate/weak.
  * generalization -- good if the standard deviation across CV folds or the
                    difference between random-split and stratified/scaffold
                    split performance is small relative to the dataset class.
  * robustness   -- good if the performance distribution under feature
                    perturbation (permutation importance re-fit) remains
                    stable.
  * applicability domain -- evaluated via validation-set coverage of the
                    training chemical space (e.g. scaffold-based leaves-one-
                    out); wide if coverage >= 0.95, else narrow.

The gate is advisory force: it never vetoes the next experiment; it only
converts a finalize decision into an additional planning step when the current
leader fails required axes, and it always defers to budget exhaustion ("compute
budget exhausted", "experiment budget exhausted") or candidate exhaustion (no
positive-utility candidate remains). Every gate decision is logged, so each
run can be audited for how long it was forced to continue and why.

2.4  Hyperparameter search

When enabled, each executed strategy's hyperparameters are optimized by
sequential model-based search: 60 runs of a Bayesian tree-structured parzen
estimator within a per-family search space (e.g. n_estimators in
{100,...,500}, learning_rate in {0.01,...,0.3}, max_depth in {2,...,9} for
gradient-boosted trees). The reported metric is the CV score. Grid search with
the same per-family space serves as the deterministic baseline.

2.5  Knowledge-graph evidence layer

The evidence layer is a read-only side car. Evidence is stored as JSONL
triples (dataset, predicate, object) with confidence accrual by run id and a
rolling window of the most recent 20 runs:

  evidence.jsonl:
    {"dataset": "esol", "predicate": "p:strategy_mean",
     "object": "maccs|svr|scaffold", "value": 0.681, "n": 3,
     "sign": -1, "run_ids": [...]}

Facts are ingested at three granularities (dataset, dataset class = task x size
bucket, and global). Static facts (model applicability rules, dataset-class
prior means from public benchmarks) are injected with a registry fingerprint so
that stale facts never poison a new registry version. The planner consumes
facts through (a) the evidence bonus defined in 2.2, (b) a rendered evidence
board grounded into the LLM prompt when an LLM is enabled, and (c) an
explanation surface: for any strategy the system can render the facts for,
facts against, and counterfactual alternatives. An empty store leaves the
planner's ranking identical to the no-evidence condition -- the layer
reallocates effort but never triggers experiments.

2.6  Dataset benchmark and evaluation protocol

Datasets (six; three regression, three binary classification):

  * ESOL - 1128 compounds, aqueous solubility (regression, RMSE)
  * FreeSolv - 642 molecules, hydration free energy (regression, RMSE)
  * Lipophilicity - 4200 compounds, logD (regression, RMSE)
  * BACE - 1513 compounds, BACE-1 inhibitor binding (binary, ROC-AUC)
  * BBBP - 2039 compounds, blood-brain barrier permeability (binary, ROC-AUC)
  * ClinTox - 1478 compounds, clinical toxicity (binary, ROC-AUC)

Protocol: each dataset is split with random 5-fold cross-validation,
single repeat, 20% held-out test fraction. Five independent seeds (0..4)
reproduce all folds and all randomness. Identical folds ensure paired
comparisons.

Scenarios (each seed x dataset runs every scenario):

  * grid        : deterministic baseline; for each enabled combination, CV
                  error of the fixed hyperparameter grid is computed and the
                  best combination is reported.
  * agent-mock  : full agent, heuristic planner (no LLM), hyperparameter
                  search on, trust gate on. (Primary scenario.)
  * agent-nosearch : as agent-mock but hyperparameter search disabled
                  (ablation of search).
  * agent-nogate : as agent-mock but the trust gate is disabled
                  (ablation of the gate; termination on first settle).
  * agent-nvidia : as agent-mock but strategy selection is refined by the
                  NVIDIA gpt-oss-20b model (ablation of the LLM; planner
                  remains heuristic in all other scenarios).

All scenarios share the model/representation library, the dataset folds, and
the primary metric (RMSE for regression, ROC-AUC for classification);
higher-is-better is reflected for classification before paired statistics.
Wall-clock runtime and the number of executed experiments are recorded per
run for the efficiency analysis.

2.7  Statistical analysis

Per-dataset, per-seed primary values are paired across scenarios. Differences
are tested with the Wilcoxon signed-rank test (two-sided); p < 0.05 is
reported as significant. Efficiency is reported as mean wall-clock time and
median experiment count per scenario, with paired runtime ratios.

  is provably identical to the no-evidence agent; all planner changes are
  conservative (caps 0.25/0.15). Cross-dataset transfer is demonstrated via
  the evidence board rather than extra experiments.
- Agentic vs AutoML: what judgement actually buys in QSAR (split choice,
  failure diagnosis, stopping discipline) vs what is noise.
- LLM role: refinement over generation -- the LLM picks among executable
  strategies rather than inventing new chemistry, which keeps the system
  auditable and cost-bounded.

--------------------------------------------------------------------------------
5  LIMITATIONS
--------------------------------------------------------------------------------

- Model library and representations are fixed and CPU-scoped; GPU-based deep
  learning pipelines are out of scope.
- The evidence store was empty at campaign start (--fresh-evidence), so the
  paper quantifies the planner's internal dynamics rather than long-horizon
  cross-dataset transfer; longer evidence accumulation is future work.
- Mock-LM runs use wholly heuristic planning; claims about LLM planning rely
  on the nvidia scenario only, and the LLM is a mid-size open-weight model
  (gpt-oss-20b), not a frontier model.
- Robustness axis relies on feature-perturbation proxies; adversarial and
  label-noise stress tests are not included.
- Single-repeat random 5-fold CV (with fixed seeds) bundles seed variation
  into the 5-seed design; a per-seed repeated-CV variant would increase
  confidence intervals.

6  EXTENSION: MULTICLASS, MULTITASK, AND OPENADMET DATASETS
--------------------------------------------------------------------------------

Beyond the six single-target regression/binary datasets of the core campaign,
we extended the harness to three additional task archetypes:

  * pampa3 (multiclass): NCATS PAMPA permeability at pH 7.4, 2033 compounds,
    three ordered classes (Low / Moderate / High permeability); primary
    metric: Matthews correlation coefficient (MCC, higher is better). Source:
    netknowledge.github.io ADMET mirror of the NCATS PAMPA assay.
  * tox21 (multitask binary): 8014 compounds, 12 aligned nuclear-receptor /
    stress-response assay endpoints; primary metric: mean ROC-AUC across the
    12 tasks (identical folds shared across targets). Source: MoleculeNet
    (deepchemdata S3).
  * pxr (OpenADMET): PXR induction pEC50, 4139 compounds from the OpenADMET
    PXR blind-challenge training split; primary metric: RMSE. Source:
    huggingface.co/datasets/openadmet (openadmet/pxr-challenge-train-test).

Implementation. Endpoint detection now recognizes 2+ aligned target columns as
a multitask endpoint (uniform task type required; Tox21-style). The experiment
runner trains one estimator per target under shared folds, shared
hyperparameter search, and shared row masks; trust outputs are merged per
metric (means averaged, stds kept at the maximum), and planner/budget cost
estimates inherit the base task treatment. Multiclass (n_classes up to 12)
is fully wired through models (n_classes fed to estimators), metrics (adaptive
binary/macro F, MCC as primary), and the trust evaluator. No changes were
required in the knowledge evidence layer: new task types simply produce their
own dataset-class buckets.

Preliminary single-seed smoke results (seeds 0, to be replaced by the full
5-seed campaign):

  dataset   task            grid     agent-mock   agent model (split)
  -------   ------------    ------   ----------   ------------------------
  tox21     multitask_binary 0.703   0.739        rdkit_fp+extra_trees[scaffold]
  pampa3    multiclass       0.310   0.307        morgan+xgboost[random]
  pxr       regression       1.184   0.842        maccs+xgboost[scaffold]

(FILL: final table + pairwise stats after the 5-seed extension campaign.)

Remarks. (i) The single-seed numbers suggest the agent's advantage is largest
on more difficult splits (pxr: scaffold-validated xgboost vs ridge grid) and
neutral on an already-easy multiclass problem. (ii) On tox21 the agent's
hyperparameter search + scaffold-split validation exceeds the static RF grid
with four grid points. (iii) Multitask aggregation via mean primary keeps
the trust gate unchanged: verdicts are computed on the aggregated metrics.

Limitation: the multitask runner aggregates per-target metrics rather than
fitting a shared-parameter multitask model; representation sharing across
targets is therefore implicit (same representation matrix) rather than
parameterized.
